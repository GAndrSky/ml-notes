5.9 Object Detection

Object detection отвечает сразу на два вопроса: какие объекты есть на изображении и где находится каждый из них.

Почему важно

Детектор отвечает на два вопроса сразу: что за объект и где он находится. Это делает задачу сложнее классификации — нужно одновременно предсказать класс и bounding box.

  • Anchor boxes и YOLO — как предсказываются множество объектов
  • NMS (Non-Maximum Suppression) — как убрать дублирующие детекции
  • mAP — основная метрика детекции и как её считать

TL;DR

Detection — это классификация плюс локализация. Модель предсказывает bounding boxes, вероятности классов и confidence. Сложные части — сопоставить предсказания с ground truth, подавить дубликаты и оценить качество локализации через IoU и mAP.

Зачем это нужно

Detection используется в автономном вождении, ритейл-аналитике, медицинской визуализации, OCR-пайплайнах, контроле качества на производстве, модерации, спортивной аналитике и робототехнике. Обычно она чувствительнее к продакшену, чем классификация: боксы должны быть точными в пространстве, стабильными между кадрами и достаточно быстрыми для real-time.

Bounding boxes и IoU

Детектор обычно предсказывает боксы как координаты. Стандартная мера качества локализации — Intersection over Union.

IoU(A,B) = area(intersection) / area(union)
What the symbols mean
Apredicted boxBox proposed by the model.
Bground-truth boxHuman-labeled correct object location.
A cap BoverlapArea where predicted and true boxes overlap.
A cup BunionTotal area covered by either box.
Intuition: IoU is high only when the predicted box covers the object and does not include too much extra area.
Analogy: two stickers on the same object should overlap almost perfectly.
Numeric example: if overlap is 40 pixels and union is 80 pixels, IoU = 0.5.

Anchors, YOLO и one-stage detection

Anchor-based детекторы стартуют с заранее заданных опорных боксов: сеть предсказывает смещения относительно anchors и оценки класса/objectness. Модели в стиле YOLO делят изображение на позиции предсказания и выдают множество кандидатов за один forward pass (современные версии YOLO бывают и anchor-free).

b_x = sigma(t_x) + c_x, b_w = p_w exp(t_w)
What the symbols mean
t_x,t_wraw predictionsNetwork outputs before box decoding.
c_xcell coordinateGrid location where the box is predicted.
p_wanchor widthPrior width of the reference box.
sigmasigmoidConstrains center offset into a stable range.
Intuition: the detector does not invent boxes from scratch; it adjusts reference boxes.
Analogy: resize and move a template frame until it fits the object.

Компромисс YOLO: очень быстро и удобно для продакшена, но из-за плотных кандидатов нужны аккуратные пороги confidence и NMS.

Non-Maximum Suppression

NMS удаляет дубликаты: сортируем боксы по confidence, оставляем самый уверенный и подавляем соседние боксы с высоким IoU, затем повторяем.

keep box_i if IoU(box_i, selected_box) < threshold

Типичные пороги: confidence 0.25–0.5, IoU для NMS 0.45–0.7. Чем ниже порог NMS, тем больше дубликатов удаляется — но можно удалить и близко стоящие разные объекты.

DETR: detection как предсказание множества

DETR обходится без anchors и NMS: он использует transformer object queries и двудольное сопоставление предсказанных боксов с объектами ground truth.

loss = class_loss + lambda_box L1(box, box*) + lambda_iou (1 - GIoU(box, box*))

Ключевая идея: модель предсказывает множество объектов фиксированного размера, а Hungarian matching решает, какое предсказание соответствует какому объекту ground truth.

Метрики: mAP

Mean Average Precision суммирует precision-recall кривые по классам и порогам IoU. mAP в стиле COCO усредняет по IoU от 0.50 до 0.95 и поэтому сильно вознаграждает точные боксы.

Рабочий код: IoU и NMS

# What it does: compute IoU and run greedy NMS
# Input shapes: boxes=(N,4) in xyxy format, scores=(N,)
# Output shape: kept indices=(K,)
import numpy as np

def iou(a, b):
    x1 = max(a[0], b[0]); y1 = max(a[1], b[1])
    x2 = min(a[2], b[2]); y2 = min(a[3], b[3])
    inter = max(0, x2 - x1) * max(0, y2 - y1)
    area_a = max(0, a[2]-a[0]) * max(0, a[3]-a[1])
    area_b = max(0, b[2]-b[0]) * max(0, b[3]-b[1])
    return inter / (area_a + area_b - inter + 1e-9)

def nms(boxes, scores, threshold=0.5):
    order = scores.argsort()[::-1]
    keep = []
    while order.size:
        i = order[0]
        keep.append(i)
        rest = order[1:]
        # dtype=bool: when rest is empty, np.array([]) is float and cannot index
        mask = np.array([iou(boxes[i], boxes[j]) < threshold for j in rest], dtype=bool)
        order = rest[mask]
    return [int(k) for k in keep]

boxes = np.array([[0,0,10,10], [1,1,11,11], [30,30,40,40]], dtype=float)
scores = np.array([0.9, 0.8, 0.7])
print(nms(boxes, scores, threshold=0.5))
# Gotchas: use consistent box format; tune NMS threshold per dataset density.

Частые ошибки

  • Отчитываться accuracy классификации вместо метрик детекции.
  • Учить на боксах в несогласованных форматах координат.
  • Один порог confidence для всех классов при сильном дисбалансе.
  • Игнорировать качество на мелких объектах и ограничения по latency.

Проверь себя

Вопросы для самопроверки

  1. В чём принципиальная разница между one-stage и two-stage детекторами?

    Two-stage (Faster R-CNN): сначала генерирует region proposals (RPN), затем классифицирует их — более точный, но медленный. One-stage (YOLO, SSD, FCOS): напрямую предсказывает bounding boxes и классы по сетке — быстрее, лучше для real-time, но исторически уступал в точности на мелких объектах.

  2. Что такое anchor boxes и зачем они нужны?

    Anchor boxes — предустановленные прямоугольники разных масштабов и соотношений сторон в каждой ячейке сетки. Модель предсказывает поправки (δx, δy, δw, δh) к anchors, а не координаты напрямую. Это стабилизирует обучение и покрывает разные размеры объектов.

  3. Что такое Non-Maximum Suppression (NMS) и зачем он нужен?

    NMS удаляет дублирующиеся детекции: сортирует боксы по confidence, берёт лучший, удаляет все боксы с IoU > порога (обычно 0.5), повторяет. Это оставляет один бокс на каждый объект. Без NMS детектор выдаёт множество перекрывающихся предсказаний для одного объекта.

  4. Что такое IoU и как он используется при обучении детектора?

    IoU (Intersection over Union) = площадь пересечения / площадь объединения двух боксов. Используется для: (1) matching predictions к GT (IoU>0.5 → positive), (2) NMS, (3) как метрика качества (mAP вычисляется при разных IoU порогах). IoU-loss напрямую оптимизирует эту метрику.

Как закрепить тему: Object Detection

Блок связывает теорию с практикой: где применять идею, какие ошибки проверять и как развиваться дальше.

Когда применять

  • Используй YOLO для real-time задач, DINO/DETR для высокой точности.
  • mAP@0.5 и mAP@0.5:0.95 — стандартные метрики; проверяй отдельно по размерам объектов.
  • Начинай с pretrained COCO-модели и fine-tune на своих данных.

Типичные ошибки

  • Не настраивать NMS-threshold под свою задачу — дефолт 0.5 не всегда оптимален.
  • Оценивать только на IoU=0.5 и не смотреть на small objects отдельно.
  • Забывать о data augmentation (mosaic, mixup, random crop) для детекции.

Что тюнить / проверить

  • IoU threshold для positive/negative matching (0.5 стандарт).
  • Confidence threshold для inference.
  • Anchor scales/ratios (для anchor-based) или stride (для anchor-free).

5.11 Contrastive Learning and CLIP

Contrastive learning учит представления, притягивая соответствующие пары и отталкивая несоответствующие.

Почему важно

CLIP научил модель понимать связь между изображениями и текстом без явных меток. Contrastive learning — подход, извлекающий универсальные представления из пар «похожее–непохожее».

  • SimCLR (contrastive) и DINO (self-distillation без негативов) — self-supervised обучение представлений

TL;DR

CLIP учит общее пространство эмбеддингов для изображений и текста: у соответствующих пар «картинка — подпись» высокая cosine similarity, у несоответствующих — низкая. Это позволяет zero-shot классификацию: изображение сравнивают с текстовыми промптами.

Зачем это нужно

Contrastive learning лежит в основе современного поиска, моделей эмбеддингов, мультимодальных систем, self-supervised предобучения в зрении и zero-shot классификаторов в стиле CLIP. Он превращает «метки» в отношения между примерами.

InfoNCE loss

Для одного якорного примера InfoNCE делает positive более похожим, чем все negatives в batch.

L_i = -log exp(s_i,i / tau) / sum_j exp(s_i,j / tau)
What the symbols mean
s_i,jsimilarity scoreUsually cosine similarity between anchor i and candidate j.
i,ipositive pairThe correct matching pair, such as an image and its caption.
jcandidatesAll possible matches in the batch: one positive and many negatives.
tautemperatureControls how sharp the softmax distribution is.
Intuition: the correct pair must win a classification problem against all other batch items.
Analogy: match a photo to the correct caption among many captions.
Numeric example: if the positive similarity is much larger than negatives, its softmax probability approaches 1 and loss approaches 0.

SimCLR: self-supervised contrastive learning в зрении

SimCLR создаёт два аугментированных вида одного изображения — это positives; остальные изображения в batch — negatives. Модель учит инвариантности: crop, color jitter, blur и небольшие геометрические изменения не должны менять «идентичность» объекта.

  • Encoder: CNN или ViT отображает изображение в представление.
  • Projection head: MLP отображает представление в пространство для contrastive loss.
  • Аугментации: определяют, какую информацию модель должна игнорировать.

Архитектура CLIP

CLIP использует два encoder-а — для изображений и для текста. Он обучается на парах «картинка — подпись» и оптимизирует contrastive loss в обе стороны: image→text и text→image.

logits = normalize(image_emb) @ normalize(text_emb)^T / tau
What the symbols mean
image_embimage embeddingVector produced by the image encoder (e.g. ViT). Shape: N×d, one row per image in the batch.
text_embtext embeddingVector produced by the text encoder (Transformer). Shape: N×d, one row per caption.
normalizeL2 normalizationDivides each vector by its norm so all embeddings lie on the unit sphere. Ensures dot product equals cosine similarity.
^TtransposeTurns text_emb from N×d into d×N. After @, result is N×N: entry (i,j) is the cosine similarity between image i and text j.
@matrix productComputes all N² image-text similarities at once. The diagonal holds the correct (matched) pairs; off-diagonal are negatives.
tautemperatureLearnable scalar (typically ~0.07). Low tau sharpens the softmax — correct pairs must be clearly more similar than all negatives.
Intuition: the result is an N×N logit matrix. Training pushes diagonal entries (matched pairs) high and off-diagonal (mismatches) low — simultaneously in both image-to-text and text-to-image directions.
Analogy: put images and sentences on the same map so matching pairs land near each other; all others are pushed apart.
Numeric example: batch N=4. image_emb @ text_emb^T gives a 4×4 matrix. Divide by tau=0.07 → cross-entropy on rows (image→text) and columns (text→image). Loss is 0 only when each image ranks its caption first across all N candidates.

Zero-shot классификация

Чтобы классифицировать изображение, кодируем промпты вроде «a photo of a cat», «a photo of a dog», «a photo of a car» и выбираем текстовый эмбеддинг, наиболее похожий на эмбеддинг изображения.

Формулировка промпта важна: CLIP не просто распознаёт метки, а сравнивает изображение с описаниями на естественном языке.

Рабочий код: contrastive logits

# What it does: compute CLIP-style contrastive logits
# Input shapes: image_emb=(B,d), text_emb=(B,d)
# Output shape: logits=(B,B)
import numpy as np

def normalize(x, eps=1e-9):
    return x / (np.linalg.norm(x, axis=1, keepdims=True) + eps)

image_emb = np.array([[1.0, 0.0], [0.2, 0.8]])
text_emb = np.array([[0.9, 0.1], [0.0, 1.0]])
tau = 0.07
logits = normalize(image_emb) @ normalize(text_emb).T / tau
print(logits)
# Gotchas: embeddings must be normalized; temperature strongly changes confidence.

Частые ошибки

  • Считать negatives всегда настоящими negatives: в больших batch встречаются false negatives.
  • Не продумывать аугментации в self-supervised contrastive learning.
  • Считать объяснения CLIP причинными, потому что текстовое сходство выглядит интуитивно.
  • Использовать cosine similarity, не проверив нормализацию эмбеддингов.

Упражнения: Contrastive Learning и CLIP

Проверка темы - понимать positives/negatives, embedding alignment и zero-shot transfer.

[Foundational] Positive pair

Что является positive pair в SimCLR? Решение: две augmentations одного и того же изображения.

[Foundational] CLIP pairs

Что является positive pair в CLIP? Решение: изображение и соответствующий текстовый caption.

[Intermediate] Temperature

Как temperature влияет на contrastive loss? Решение: низкая temperature делает softmax резче и сильнее фокусирует hard negatives.

[Intermediate] Zero-shot classification

Как CLIP делает zero-shot classification? Решение: сравнивает image embedding с text embeddings prompt-ов классов.

[Hard] False negatives

Почему false negatives вредят contrastive learning?

Решение. В contrastive loss все остальные примеры в batch считаются negatives. Если в batch из 512 изображений есть две разные фотографии собак, модель штрафуется за их сходство — её учат раздвигать то, что должно быть рядом. Чем больше batch и чем меньше «классов» в данных, тем больше таких ложных negatives: при 10 реальных классах и batch 512 почти у каждого якоря ~50 «негативов» на самом деле того же класса. Последствия: размытые кластеры, хуже качество на downstream. Смягчения: supervised contrastive (SupCon), где объекты одного класса — positives; удаление или понижение веса подозрительно похожих negatives; меньшая temperature компенсирует не всё; в CLIP частично помогает разнообразие текстов-подписей.

[Intermediate] InfoNCE = cross-entropy

Покажи, что InfoNCE — это cross-entropy, где правильный «класс» — индекс positive-пары.

Решение. Для якоря q, positive k⁺ и negatives k₁…k_N: \(\mathcal{L} = -\log \frac{\exp(q\cdot k^+/\tau)}{\exp(q\cdot k^+/\tau) + \sum_j \exp(q\cdot k_j/\tau)}\). Определим «логиты» \(z_0 = q\cdot k^+/\tau\), \(z_j = q\cdot k_j/\tau\). Тогда дробь — это softmax(z)₀, а \(\mathcal{L} = -\log \mathrm{softmax}(z)_0\) — ровно cross-entropy (N+1)-классовой задачи с правильным классом 0. В batch-реализации логиты — строка матрицы \(Q K^T/\tau\), а правильный «класс» для строки i — индекс i (диагональ). Отсюда практические следствия: больше negatives = больше «классов» = сложнее задача и туже оценка; τ работает как temperature softmax.

[Foundational] Симметричный CLIP loss

Реализуй симметричный CLIP loss на NumPy: матрица logits и cross-entropy по строкам и по столбцам.

Решение. Нормализуем эмбеддинги, логиты = cos-сходства / τ; cross-entropy по строкам (image → text) и по столбцам (text → image) с правильными индексами на диагонали; loss — среднее двух.

import numpy as np

def log_softmax(z, axis):
    z = z - z.max(axis=axis, keepdims=True)
    return z - np.log(np.exp(z).sum(axis=axis, keepdims=True))

def clip_loss(img, txt, tau=0.07):
    img = img / np.linalg.norm(img, axis=1, keepdims=True)
    txt = txt / np.linalg.norm(txt, axis=1, keepdims=True)
    logits = img @ txt.T / tau                     # (B, B), positives on the diagonal
    i = np.arange(len(img))
    loss_i2t = -log_softmax(logits, axis=1)[i, i].mean()
    loss_t2i = -log_softmax(logits, axis=0)[i, i].mean()
    return (loss_i2t + loss_t2i) / 2

rng = np.random.default_rng(0)
img = rng.normal(size=(8, 16))
print("matched pairs :", round(clip_loss(img, img + 0.1 * rng.normal(size=img.shape)), 4))
print("random pairs  :", round(clip_loss(img, rng.normal(size=img.shape)), 4))   # ~ log(8) or worse

[Interview] Пределы CLIP

Объясни, почему CLIP умеет zero-shot классификацию, но ошибается в подсчёте объектов и пространственных отношениях.

Решение. Zero-shot работает, потому что CLIP научился сопоставлять изображение с описанием: «a photo of a dog» близко к фото собаки, если таких пар было много. Подсчёт и пространственные отношения ломаются по нескольким причинам: (1) подписи в интернете редко содержат точное количество и расположение («три кошки слева от стола»), сигнала мало; (2) contrastive objective награждает, если подпись подходит лучше других в batch — для этого хватает «мешка понятий» (кошка, стол), порядок и количество не нужны; (3) один глобальный эмбеддинг изображения плохо кодирует композицию. Отсюда известные провалы на бенчмарках композиционности (Winoground, ARO). Улучшают это hard negatives (перестановки слов), детальные подписи, модели с region-level признаками.

[Practice] Мини-поиск

Собери крошечное демо поиска «текст → изображение» на заранее посчитанных эмбеддингах.

Решение. Поиск — это ближайшие соседи по косинусному сходству в общем пространстве: нормализуй эмбеддинги изображений один раз, нормализуй эмбеддинг запроса и возьми top-k по скалярному произведению. Для миллионов изображений вместо полного перебора — ANN-индекс (FAISS, HNSW).

import numpy as np

def search(query_emb, image_embs, names, k=3):
    q = query_emb / np.linalg.norm(query_emb)
    m = image_embs / np.linalg.norm(image_embs, axis=1, keepdims=True)
    sims = m @ q
    top = np.argsort(-sims)[:k]
    return [(names[i], round(float(sims[i]), 3)) for i in top]

# toy "precomputed" embeddings: in practice they come from CLIP's image and text encoders
rng = np.random.default_rng(0)
concepts = {c: rng.normal(size=32) for c in ["dog", "cat", "car", "beach"]}
names = ["dog_park.jpg", "cat_sofa.jpg", "red_car.jpg", "dog_beach.jpg"]
image_embs = np.stack([concepts["dog"], concepts["cat"], concepts["car"], concepts["dog"] + concepts["beach"]])
image_embs += 0.3 * rng.normal(size=image_embs.shape)
print(search(concepts["dog"], image_embs, names))
print(search(concepts["beach"] + concepts["dog"], image_embs, names, k=1))

Проверь себя

Вопросы для самопроверки

  1. Что такое contrastive learning и в чём его основная идея?

    Contrastive learning обучает представления, делая «похожие» примеры (позитивные пары) близкими в embedding space, а «разные» (негативные) — далёкими. Не нужны метки — позитивные пары создаются через augmentations (SimCLR) или разные модальности (CLIP: изображение + текст).

  2. Как CLIP обучается и что позволяет делать в inference?

    CLIP обучается на 400M пар (изображение, текст) из интернета. Цель: максимизировать dot-product между эмбеддингами совпадающих пар и минимизировать для несовпадающих (InfoNCE loss). При inference: вычислить сходство изображения с текстовыми описаниями классов — zero-shot классификация.

  3. Что такое zero-shot transfer в контексте CLIP?

    Zero-shot transfer: модель применяется к задаче, для которой не было примеров при обучении. Для CLIP: описываем классы текстом («a photo of a dog»), получаем текстовые эмбеддинги, сравниваем с эмбеддингом тестового изображения. CLIP достигает точности ResNet-50 на ImageNet без единого обучающего примера.

  4. Почему InfoNCE loss работает хуже с маленьким батчем?

    InfoNCE рассматривает все другие примеры в батче как негативные. Маленький батч → мало негативов → задача слишком проста, representation learning неэффективен. SimCLR требует batch_size=4096+; MoCo решает это очередью (queue) из десятков тысяч негативов, закодированных медленно обновляемым momentum-encoder-ом, — независимо от размера батча.

Как закрепить тему: Contrastive Learning & CLIP

Блок связывает теорию с практикой: где применять идею, какие ошибки проверять и как развиваться дальше.

Когда применять

  • Используй CLIP embeddings для zero-shot классификации и image search.
  • Contrastive pretraining с аугментациями — мощный подход для self-supervised CV.
  • CLIP features хорошо работают как frozen backbone для downstream задач.

Типичные ошибки

  • Не масштабировать батч при contrastive learning — маленький батч = мало негативов.
  • Использовать CLIP для задач вне distribution обучения без проверки zero-shot accuracy.
  • Забывать о temperature τ — критический гиперпараметр для InfoNCE loss.

Что тюнить / проверить

  • Температура τ в InfoNCE: слишком низкая → нестабильное обучение и чрезмерный фокус на hard negatives (в том числе ложных), слишком высокая → слабый сигнал и размытые представления.
  • Batch size: больше = лучше, но дороже.
  • Augmentation strategy: сила аугментаций влияет на «сложность» positives.

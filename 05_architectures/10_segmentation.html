5.10 Segmentation

Сегментация предсказывает метку для каждого пикселя, а не одну метку на изображение или один бокс на объект.

Почему важно

Сегментация — это классификация каждого пикселя. Semantic, Instance, Panoptic — три уровня понимания изображения. U-Net используется в медицине, автопилотах, спутниковых снимках.

Что узнаешь
  • Semantic vs Instance vs Panoptic segmentation — в чём разница
  • U-Net — skip connections между encoder и decoder
  • Dice loss — почему лучше BCE при дисбалансе пикселей
  • Mask R-CNN — как детекция и сегментация объединяются
Нужно знать
  • CNN (5.1)
  • Object Detection (5.9)
  • U-Net architecture

TL;DR

Сегментация — это dense prediction. Semantic segmentation присваивает класс каждому пикселю, instance segmentation ещё и разделяет отдельные объекты. Базовая ментальная модель — U-Net: downsampling ради контекста, upsampling ради разрешения, skip connections для сохранения деталей.

Зачем это нужно

Сегментация нужна там, где важна точная форма: опухоли, дороги, разметка полос, дефекты продукции, органы, участки на спутниковых снимках, вёрстка документов, одежда, редактирование изображений. Ответ не «здесь есть собака», а «вот именно эти пиксели — собака».

Архитектура U-Net

U-Net устроена как encoder-decoder: encoder уменьшает пространственное разрешение и извлекает контекст, decoder восстанавливает разрешение, а skip connections передают признаки высокого разрешения из encoder в decoder.

decoder_l = concat(upsample(decoder_(l+1)), encoder_l)
What the symbols mean
encoder_llocal detailHigh-resolution features from encoder level l.
decoder_lreconstructed featureDecoder representation at the same spatial scale.
concatchannel mergeStacks features along channel dimension, preserving detail and context.
upsampleresolution increaseExpands lower-resolution features back toward mask size.
Intuition: deep layers know what is present; skip connections recover exactly where it is.
Analogy: combine a city map for global layout with a street-level photo for precise boundaries.

Dice coefficient и Dice loss

Dice популярен для несбалансированных масок, потому что в cross-entropy часто доминируют пиксели фона.

Dice(p,y) = (2 sum_i p_i y_i + eps) / (sum_i p_i + sum_i y_i + eps)
What the symbols mean
p_ipredicted mask valueProbability that pixel i belongs to the foreground/class.
y_itrue mask valueGround truth label for pixel i, usually 0 or 1.
sum p_i y_isoft overlapLarge when predictions align with the true mask.
epsilonstability termPrevents division by zero when masks are empty.
Intuition: Dice rewards overlap relative to total predicted and true mask size.
Analogy: two transparent cutouts are good if they cover the same shape.
Numeric example: if overlap sum is 30, predicted area is 50, true area is 40, Dice = 60/90 = 0.667.

Рабочий код: Dice score

# What it does: compute binary Dice score for segmentation masks
# Input shapes: pred=(H,W), target=(H,W)
# Output shape: scalar
import numpy as np

def dice_score(pred, target, eps=1e-7):
    pred = pred.astype(float)
    target = target.astype(float)
    intersection = np.sum(pred * target)
    return (2 * intersection + eps) / (np.sum(pred) + np.sum(target) + eps)

pred = np.array([[1,1,0], [0,1,0], [0,0,0]])
target = np.array([[1,0,0], [0,1,1], [0,0,0]])
print(dice_score(pred, target))
# Gotchas: threshold probabilities consistently; handle empty masks explicitly.

Частые ошибки

  • Использовать метки на уровне изображения, когда нужны маски на уровне пикселей.
  • Ресайзить маски билинейной интерполяцией — появляются несуществующие ID классов (нужен nearest).
  • Отчитываться только pixel accuracy на несбалансированных масках.
  • Забывать, что аугментации должны одинаково преобразовывать изображение и маску.

Упражнения: Segmentation

Проверка темы - понимать pixel-wise prediction, skip connections и segmentation losses.

[Foundational] Semantic vs instance

Чем semantic segmentation отличается от instance segmentation? Решение: semantic даёт класс каждому пикселю, instance разделяет отдельные объекты одного класса.

[Foundational] Dice score

Почему Dice полезен при маленьких объектах? Решение: он фокусируется на overlap positive masks и меньше маскируется большим фоном.

[Intermediate] U-Net skip connections

Зачем U-Net передаёт encoder features в decoder? Решение: чтобы вернуть spatial detail, потерянный при downsampling.

[Intermediate] Loss choice

Когда BCE + Dice лучше одной BCE? Решение: при сильном дисбалансе foreground/background Dice стабилизирует overlap objective.

[Hard] Boundary errors

Почему segmentation может иметь высокий pixel accuracy и плохие границы?

Решение. Пусть объект — круг радиуса 50 пикселей на изображении 512×512. Объект занимает ≈ 3% пикселей, граница (полоса толщиной 2 пикселя) — около 0.24%. Модель, которая ошибается на всей границе, теряет лишь ~0.24% pixel accuracy, а модель «всё фон» получает 97% accuracy. Поэтому pixel accuracy почти не видит ни границ, ни мелких объектов. Что использовать: IoU/Dice по классу (они нормированы на размер объекта), boundary-метрики (Boundary F1, Hausdorff distance) — в медицине и картографии граница часто и есть результат. В обучении помогают Dice/Lovász loss, взвешивание пикселей около границы (как в оригинальном U-Net), более высокое разрешение выхода и skip connections.

[Foundational] Аугментация пары

Напиши функцию аугментации, которая отражает изображение и маску одновременно.

Решение. Геометрические преобразования применяются одинаково к изображению и маске (одним и тем же случайным решением); фотометрические — только к изображению. При resize/rotate маски используется nearest-интерполяция, иначе появятся несуществующие классы.

import numpy as np

def augment(image, mask, rng):
    """image: (H, W, C) float, mask: (H, W) int class ids"""
    if rng.random() < 0.5:                       # one decision for both
        image, mask = image[:, ::-1], mask[:, ::-1]
    if rng.random() < 0.5:
        image = np.clip(image * rng.uniform(0.8, 1.2), 0, 1)   # brightness: image only
    return np.ascontiguousarray(image), np.ascontiguousarray(mask)

rng = np.random.default_rng(0)
# column index encoded in both image and mask, so we can check they moved together
img = np.repeat(np.tile(np.arange(6) / 10, (4, 1))[..., None], 3, axis=2)
msk = np.tile(np.arange(6), (4, 1))
for _ in range(4):
    a, m = augment(img, msk, rng)
    print("flipped:", m[0, 0] == 5, "| image and mask consistent:", bool((a[..., 0].argmax(1) == m.argmax(1)).all()))

[Intermediate] Mean IoU

Реализуй mean IoU для маски из 3 классов на NumPy.

Решение. IoU для класса c = |pred = c ∧ true = c| / |pred = c ∨ true = c|; mean IoU — среднее по классам, которые встречаются в разметке или в предсказании (класс, отсутствующий в обоих, пропускают, иначе 0/0). Удобно считать через confusion matrix: IoU_c = TP / (TP + FP + FN).

import numpy as np

def mean_iou(pred, true, n_classes):
    cm = np.bincount(n_classes * true.ravel() + pred.ravel(), minlength=n_classes**2).reshape(n_classes, n_classes)
    tp = np.diag(cm)
    denom = cm.sum(0) + cm.sum(1) - tp          # TP + FP + FN
    valid = denom > 0
    iou = tp[valid] / denom[valid]
    return iou.mean(), iou

true = np.array([[0, 0, 1, 1], [0, 2, 2, 1]])
pred = np.array([[0, 1, 1, 1], [0, 2, 0, 1]])
miou, per_class = mean_iou(pred, true, 3)
print(per_class.round(3), round(miou, 3))   # [0.5 0.75 0.5] 0.583

[Interview] Сегментация опухолей

Как бы ты оценивал модель сегментации опухолей, если false negatives намного дороже false positives?

Решение. Главная метрика — чувствительность на уровне пациента/очага: доля опухолей, у которых найдена хотя бы часть (lesion-wise recall), плюс Dice по найденным, чтобы оценить контур. Порог вероятности выбирают по ROC/FROC-кривой: «recall ≥ 0.98 при не более N ложных очагов на снимок», а не 0.5. В loss — взвешивание FN (Tversky/focal Tversky с β > α) или повышенный вес класса опухоли. Обязательно: оценка по сегментам (размер опухоли, аппарат, клиника), confidence intervals (данных мало), сравнение с разбросом между врачами (inter-rater Dice) и разбор каждого пропуска. В продакшене модель — второе мнение, финальное решение за врачом.

Проверь себя

Вопросы для самопроверки

  1. В чём разница между semantic и instance segmentation?

    Semantic segmentation: каждому пикселю присваивается класс (все «люди» — один класс). Instance segmentation: каждому объекту-экземпляру — отдельная маска (человек_1, человек_2). Panoptic segmentation объединяет оба подхода: считаемые объекты (things) + фон (stuff).

  2. Почему FCN (Fully Convolutional Network) стал основой для семантической сегментации?

    FCN заменяет полносвязные слои свёрточными, что позволяет обрабатывать изображения произвольного размера и получать пространственные карты предсказаний. Для каждого пикселя независимо предсказывается класс. Upsampling (transposed conv или bilinear) восстанавливает пространственное разрешение.

  3. Что такое U-Net и почему skip-connections критичны для сегментации?

    U-Net: энкодер (downsampling) + декодер (upsampling) + skip-connections между соответствующими уровнями. Skip-connections передают fine-grained пространственную информацию (текстуры, края), потерянную при downsampling. Это позволяет точно сегментировать мелкие детали.

  4. Как Mask R-CNN расширяет Faster R-CNN для instance segmentation?

    Mask R-CNN добавляет к Faster R-CNN третью голову: помимо классификации и regression боксов, для каждого предложенного региона предсказывает бинарную маску 28×28 для каждого класса (из признаков RoIAlign 14×14), которую затем масштабируют до размера бокса. RoIAlign (в отличие от RoIPool) сохраняет субпиксельную точность через билинейную интерполяцию.

Как закрепить тему: Semantic & Instance Segmentation

Блок связывает теорию с практикой: где применять идею, какие ошибки проверять и как развиваться дальше.

Когда применять

  • Используй U-Net для медицинских изображений, Mask R-CNN для instance.
  • IoU per class и mIoU — стандартные метрики сегментации.
  • Skip-connections — критическая деталь архитектуры, не удаляй их для «упрощения».

Типичные ошибки

  • Оценивать только pixel accuracy — она вводит в заблуждение при дисбалансе классов.
  • Не проверять качество на редких классах (маленькие объекты, редкие категории).
  • Игнорировать RoIAlign в Mask R-CNN — RoIPool теряет субпиксельную точность.

Что тюнить / проверить

  • Encoder backbone: ResNet-50/101 vs ViT — баланс точности и скорости.
  • Loss weight для разных классов при дисбалансе.
  • Output stride: 8 vs 16 — компромисс разрешения и скорости.

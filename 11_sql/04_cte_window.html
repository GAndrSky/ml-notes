11.4 CTE и оконные функции

CTE делают длинные запросы читаемыми, а оконные функции считают значения «по соседним строкам», не схлопывая их: рейтинги, предыдущие значения, накопительные суммы. В конце урока — финал расследования.

Зачем это знать

Оконные функции — самая частая «сложная» тема SQL-собеседований и главный инструмент для признаков во времени: дни с прошлой покупки, ранг товара, скользящие суммы.

Что узнаешь
  • Разбивать запрос на шаги через WITH
  • Нумеровать строки в группах (ROW_NUMBER, RANK)
  • Брать соседние строки (LAG, LEAD) и считать накопительные суммы

WITH: именованные шаги

Common Table Expression (CTE) — подзапрос с именем, объявленный перед основным запросом. Можно объявить несколько через запятую; каждый следующий видит предыдущие.

Оконные функции

Оконная функция считается для каждой строки по «окну» связанных строк и не уменьшает их число. Синтаксис: функция() OVER (PARTITION BY … ORDER BY …). PARTITION BY — как GROUP BY, но без схлопывания; ORDER BY — порядок внутри окна.

ROW_NUMBER даёт уникальные номера, RANK — одинаковые при равенстве с пропусками (1, 1, 3), DENSE_RANK — без пропусков (1, 1, 2). Окна вычисляются после WHERE и GROUP BY, поэтому отфильтровать «первое место» можно только во внешнем запросе.

Вопросы для самопроверки

  1. Чем оконная функция отличается от агрегата с GROUP BY?

    GROUP BY схлопывает группу в одну строку. Оконная функция считает значение по группе (окну), но оставляет все строки: можно вывести и цену товара, и максимум по его категории, и ранг внутри неё — в одной строке.

  2. Чем отличаются ROW_NUMBER, RANK и DENSE_RANK?

    При равных значениях ROW_NUMBER всё равно даёт разные номера (порядок среди равных произвольный, если не добавить столбец в ORDER BY), RANK даёт одинаковый ранг и пропускает следующие (1, 1, 3), DENSE_RANK — одинаковый без пропусков (1, 1, 2). Для «топ-1 на группу» обычно берут ROW_NUMBER, для «все лидеры с одинаковым результатом» — RANK.

  3. Почему нельзя написать WHERE ROW_NUMBER() OVER (...) = 1?

    Оконные функции вычисляются после WHERE, GROUP BY и HAVING — на этапе SELECT. Поэтому номер сначала считают во внутреннем запросе или CTE, а фильтруют во внешнем: SELECT … FROM (SELECT …, ROW_NUMBER() OVER (…) AS rn …) WHERE rn = 1.

  4. Зачем нужны CTE, если есть подзапросы?

    CTE делают то же самое, но читаются сверху вниз как последовательность шагов с понятными именами, и один CTE можно использовать в запросе несколько раз. Рекурсивные CTE (WITH RECURSIVE) умеют то, чего не умеют подзапросы: обход иерархий и генерацию последовательностей.

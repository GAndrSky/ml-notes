11.2 Агрегация и GROUP BY

Агрегатные функции сворачивают много строк в одно число, а GROUP BY делает это отдельно для каждой группы. Так отвечают на вопросы «сколько», «сколько в сумме» и «у кого больше всего».

Зачем это знать

Любой отчёт, метрика и большинство признаков для модели — агрегаты: число покупок клиента, средний чек, доля возвратов. Ошибки в группировке — частая причина неверных цифр.

Что узнаешь

  • Группировать строки через GROUP BY

Часть 2. Масштаб проблемы

Елена хочет цифры: сколько всего заказов, какая доля возвращается и кто из сотрудников одобряет возвраты. Отдельные строки больше не помогут — пора считать.

Агрегатные функции

COUNT(*) — число строк, COUNT(столбец) — число не-NULL значений, COUNT(DISTINCT столбец) — число разных значений. SUM, AVG, MIN, MAX работают с числами (а MIN/MAX — и со строками, и с датами). Все они пропускают NULL.

GROUP BY

GROUP BY делит строки на группы с одинаковыми значениями и считает агрегат в каждой. В SELECT можно выводить только столбцы группировки и агрегаты.

HAVING и порядок выполнения

Запрос записывается в одном порядке, а выполняется в другом:

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

WHERE фильтрует строки до группировки и не видит агрегатов; HAVING фильтрует уже готовые группы. Поэтому «клиенты с более чем 8 заказами» — это HAVING:

Проверь себя

Вопросы для самопроверки

  1. Чем отличаются COUNT(*), COUNT(col) и COUNT(DISTINCT col)?

    COUNT(*) считает все строки, COUNT(col) — строки, где col не NULL, COUNT(DISTINCT col) — число разных не-NULL значений. Например, число заказов и число покупателей в таблице заказов — это COUNT(*) и COUNT(DISTINCT customer_id).

  2. Почему условие на агрегат нельзя написать в WHERE?

    WHERE выполняется до группировки, когда агрегатов ещё нет: он отбирает отдельные строки. Условия на группы пишут в HAVING, который выполняется после GROUP BY. Фильтры по обычным столбцам лучше оставлять в WHERE — тогда в группировку попадает меньше строк.

  3. Как AVG обрабатывает NULL и чем это опасно?

    AVG пропускает NULL: среднее считается только по известным значениям. Если пропуски не случайны (например, сумму не записали для отменённых заказов), среднее будет смещено. Если пропуск должен считаться нулём, нужно явно написать AVG(COALESCE(col, 0)).

  4. Что будет, если вывести в SELECT столбец, которого нет в GROUP BY?

    В PostgreSQL и большинстве СУБД — ошибка: для группы непонятно, какое значение выбрать. SQLite и старый MySQL молча вернут значение из произвольной строки группы — запрос работает, но результат может быть неверным. Нужно либо добавить столбец в GROUP BY, либо обернуть его в агрегат.

11.1 SQL: первые запросы

SQL — язык, на котором спрашивают у базы данных. В этом блоке вы расследуете дело интернет-магазина «Вольт», а запросы выполняются прямо в браузере — на настоящей SQLite.

Зачем это знать

Данные для ML почти всегда лежат в базах. SQL спрашивают на большинстве собеседований аналитиков, data scientist-ов и ML-инженеров, а сборка датасета и признаков начинается с запроса.

Что узнаешь
  • Выбирать столбцы (SELECT) и фильтровать строки (WHERE)
  • Сортировать и ограничивать выдачу (ORDER BY, LIMIT)
  • Искать по шаблону (LIKE) и правильно работать с NULL
Нужно знать
  • Ничего — блок начинается с нуля

Дело о тихих возвратах

У вас есть доступ к базе магазина: клиенты, товары, заказы, возвраты и сотрудники. За пять уроков вы найдёте, кто стоит за возвратами, и подготовите данные для модели, которая будет ловить такое заранее.

Таблицы, строки, столбцы

Реляционная база — набор таблиц. Строка — один объект (клиент, заказ), столбец — его свойство (имя, дата). У каждой таблицы есть первичный ключ — столбец, однозначно определяющий строку (customer_id у клиентов). Таблицы связаны ключами: в заказе хранится customer_id покупателя, а не его имя.

SELECT и FROM

Самый простой запрос — какие столбцы взять (SELECT) и из какой таблицы (FROM). Точка с запятой завершает запрос. Ключевые слова пишут заглавными по традиции — регистр для них не важен.

WHERE: фильтр строк

WHERE оставляет только строки, для которых условие истинно. Сравнения: =, <> (не равно), <, >, <=, >=. Условия объединяют через AND, OR, NOT; удобные сокращения — BETWEEN a AND b (включая границы) и IN (…).

Текст пишется в одинарных кавычках. Даты в этой базе — строки YYYY-MM-DD, и их можно сравнивать как строки: '2025-03-01' < '2025-12-31'.

ORDER BY и LIMIT

Без ORDER BY база вправе вернуть строки в любом порядке. ORDER BY столбец DESC — по убыванию, ASC (по умолчанию) — по возрастанию; можно сортировать по нескольким столбцам. LIMIT n оставляет первые n строк — после сортировки.

LIKE и NULL

LIKE ищет по шаблону: % — любые символы, _ — ровно один. NULL означает «значение неизвестно»: сравнение = NULL никогда не истинно, поэтому пишут IS NULL / IS NOT NULL.

Второй запрос заранее показывает агрегаты из следующего урока: COUNT(email) не считает строки, где email — NULL.

Песочница

Пробуйте любые запросы. База восстанавливается автоматически, если что-то изменить или удалить.

Задания

Ответ засчитывается, если результат совпадает с эталонным: те же строки и то же число столбцов в том же порядке. Названия столбцов не проверяются. Прогресс сохраняется в браузере.

Проверь себя

Вопросы для самопроверки

  1. Почему без ORDER BY нельзя полагаться на порядок строк?

    Таблица — это множество строк без порядка. База возвращает их в том порядке, который удобен плану выполнения (порядок хранения, индекса, параллельных потоков), и он может меняться между запусками и версиями. Любой порядок, который важен (топ-N, «последний заказ»), задаётся явным ORDER BY, а при равенстве значений — дополнительным столбцом.

  2. Почему WHERE email = NULL не находит строки с пустым email?

    NULL — «неизвестное значение», и любое сравнение с ним даёт неизвестность (UNKNOWN), а WHERE пропускает только TRUE. Поэтому для проверки используют IS NULL и IS NOT NULL. Та же логика влияет на NOT IN и агрегаты: COUNT(email) пропускает NULL.

  3. Чем LIKE 'Pro%' отличается от LIKE '%Pro%'?

    % заменяет любую последовательность символов. 'Pro%' — строки, которые начинаются с «Pro», '%Pro%' — содержащие «Pro» в любом месте. Шаблон с % в начале не может использовать обычный индекс по столбцу, поэтому на больших таблицах работает медленнее.

  4. Почему SELECT * не рекомендуют в рабочих запросах?

    Запрос читает и передаёт лишние столбцы (медленнее, особенно в колоночных хранилищах), результат меняется, если в таблицу добавят столбец, а читателю непонятно, какие данные реально нужны. Для быстрого просмотра данных SELECT * … LIMIT 10 — нормально.
